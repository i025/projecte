# bw_0073：VLM-guided SLIC Grounding

**本轮没有证明 SLIC 能在保留主要功能内容的同时，稳定改善 Direct ROI。** C1 能将直线边界变成视觉块边界，但也会截断台面、柜体、椅子或吊灯边缘，并新增天花板/地板内容。C2 的完整性保护明显减少删除，但多数边界又回到原 ROI 附近，背景排除收益不明显。

建议继续使用经人工审核的 Direct Box/Polygon 作为粗评价范围，本轮不把 SLIC 加入正式默认 Grounding。没有看到足够明确的无损收益，因此按条件停止在 bw_0073，没有扩展 bw_0074、bw_9064，也没有继续调参。

## 方法及完整性保护

**A：Direct Box；B：Direct Polygon。** 原分辨率基线 Mask 与历史文件逐字节一致。两个输入分别运行 C1/C2，结果不能互相冒充 SLIC 收益。

**C1：Overlap Selection。** 对整个超像素计算 `p = ROI 内像素数 / 超像素总像素数`，`p≥0.5` 选择整块，其余排除。p 是几何交叠比例，不是语义正确概率。C1 是有意保留的简单基线，没有隐藏其完整性损失。

**C2：Boundary-Aware Selection + 保守保护。**

1. `p≥0.8` 为内部种子，`p≤0.2` 为外部种子；只用共享边界构造相邻超像素关系。
2. 共享边界取 RGB 灰度 Sobel 梯度均值。相邻支持权重为 `共享边界长度 / (1 + 梯度 / 全图共享边界梯度的75%分位数)`；强边界降低借用邻居的程度。没有使用平均颜色相似度作为删除依据。
3. 使用一次性邻居种子支持票 v，分数为 `0.75×(2p−1)+0.25×(2v−1)`。中间块只有在有邻居证据、分数绝对值≥0.15且位置与邻居方向一致时，才按整块决定；否则保留该超像素中的原 ROI 片段。
4. 保留原 ROI 向内 2 个工作像素的核心；若某个分离的原 ROI 组件侵蚀后完全消失，则保护该小组件的全部原像素。没有区域编号、名称、目标位置或区域优先级规则。

**保护不等于语义完整性证明。** 2 像素核心仍可能丢失细长突出边缘；所有输出继续 uncertain。C2 由整块选择与受保护的原 ROI 片段共同组成，**不是纯整块超像素并集**。每区图单独展示“选中整块”和“最终 ROI”，避免混淆。

保护前的 C2 原始提案保存在 `slic_*/{Box,Polygon}_proposals/R*_C2_raw.png`，HTML 中可展开查看；每个超像素的 p、邻接票、选择和不确定片段记录在同目录 `selection.json`。没有通过保护掩盖原始提案可能删除的内容。

## 逐区视觉检查

| Region | C1 观察 | C2 观察 | 当前结论 |
| --- | --- | --- | --- |
| R1 水槽区 | 窗口/墙面及右端台面、柜体边缘发生整块进出；400 粒度右边缘有截断风险 | 主体得到保护，但仍带入原墙面/地板，整体更接近初始 ROI | 无稳定无损收益；水槽、搁板、壁灯与柜体边缘待审 |
| R2 岛台区 | 没有像此前 SAM 那样丢掉整个岛台，但吊灯上缘、岛台前缘和椅子边缘被削去；同时出现新的背景扩张 | 岛台、椅子与吊灯主要部分大致保留，边缘仍有删除；400 Polygon 有额外小碎片 | C1 不应自动替换；C2 的高保留比例不能证明没有语义漏项 |
| R3 后方料理区 | 局部顺着背板/柜体视觉块走，也改变台面与前景摆物边界 | 核心恢复后，原有前景混入问题大多延续 | 梯度/邻接不能判断器皿、绿植的前后景语义归属 |
| R4 高柜区 | 某些斜边更贴柜体，但同时产生锯齿、地板扩张和柜体边缘截断；两种粒度不一致 | 大面积柜体保留，但边界收益变小；400 Polygon 多出小分离块 | 有局部视觉贴合，不足以认定整体比 Direct Polygon 更合适 |

Polygon 的 R2 仍保留“上方吊灯 + 下方岛台/椅子”的多个可见组件；不能把它们强制合成一个连通区域。C2 也未保证拓扑完全不变：400 粒度下 R2 从原来的 2 个组件变为 3 个，R4 从 1 个变为 2 个。额外小块不是新发现的语义实例。

Direct Polygon 原本的内容遗漏也不会自动被 SLIC 修复，例如 R1 部分壁灯问题仍需人工审核。看似更窄的 Polygon + SLIC 不能直接与 Box 基线相比后宣称 SLIC 更好。

## 原图网格与导出

原图基线为 **7952×4333**，SLIC 决策使用已验证来源的 **1536×837** 工作网格。C1/C2 最终 Mask 以最近邻投影回原始分辨率，保存于各方法的 `_native/` 目录；对应 `evidence.json` 可由现有证据加载器读取，全部候选仍不参与正式评分。

已有原图 ROI 经过“原图→工作网格→原图”本身会有量化变化。`grid_audit.json` 保存这个不使用 SLIC 选择的控制量；`native_pixel_changes.csv` 保存实际原图候选相对原图基线的变化，其中包含该网格运输效应。**不能把这些运输像素全部归因于 SLIC。** 上文方法比较统一在决策网格上进行。

## 泛化检查与六个结论

1. **边界改善了吗？** 局部有视觉块贴合，但常伴随锯齿、扩张或截断，没有稳定改善。
2. **背景减少了吗？** C1 有些位置减少墙面/地板，也在别处增加背景。C2 保护内容后大多保留原背景，没有一致的背景排除收益。
3. **是否遗漏重要内容？** C1 有台面、柜体、椅子及吊灯边缘的可见风险。C2 保住主要范围，没有出现 SAM 实验式的大块岛台消失，但细边缘仍不确定，不能宣称无损。
4. **Box 还是 Polygon 更合适？** Polygon 输入的功能范围通常更紧凑，但这是已有 VLM Polygon 的作用。两种输入均未显示 SLIC 带来稳定增益；不能把它们的初始差异算成 SLIC 收益。Box 的内部大面积背景也不能靠边界超像素自动识别。
5. **能跨场景吗？** **未执行，无法判断。** bw_0073 没有达到“保留主要内容且有明确改善”的扩展门槛，故没有运行 bw_0074/bw_9064。不是模型、GPU 或 Plan 缺失造成的跳过，也没有借助它们调参。
6. **是否加入正式默认？** 当前不建议。简单 Direct ROI 更适合先进入人工审核及下一阶段局部评价验证；SLIC 可保留为按需候选分析工具。未获得像素 GT，也未测下游能量敏感性，不能宣称任何方法已普遍足够或最优。

`decision.json` 指向原始 Direct ROI 作为待审核回退来源，没有自动冻结一个最佳 SLIC 结果。所有参数与失败例都保留，不再进行第二轮边界调参。

## 实际执行、测试与成本

- **138 项 CPU 测试通过**，包含 p 的正确分母/阈值、强边界亲和力、内部核心和分离小组件保护、标签重编号/重复运行不变性、非法网格拒绝、原图导出及 Evidence 加载器。初次离线单测发现 NumPy 返回索引维度兼容问题，已在真实图运行前修正，没有据此调整方法参数。
- 实际缓存的 C1/C2、原始 C2 提案及原图投影均做了离线确定性重放检查；结果见 `offline_replay_check.json`。
- 构图合计约 **0.304 s**；四次“四区选择”合计约 **0.442 s**。完整脚本包含原图投影、PNG/HTML 与多组逐区图，墙钟 **89.402 s**；不把可视化耗时冒充选择算法耗时。
- CPU 线程限制为 2；没有 GPU、SAM2/SAM3、DINO、付费 VLM、Blender、Agent 执行、SLIC 重算、依赖下载、正式评分或自动 Git 提交。
- 原始 RGB/历史结果没有修改。新增源码只有实验脚本和离线测试，正式 Evidence Extraction、五类能量、3D Structural Energy 与 Region Planning Prompt 均未改变。
